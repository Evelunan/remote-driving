# 主视角失效与控制授权

驾驶员点击「开始控制」后，驾驶端等待同一辆车的主视角持续收到新帧、Qt 完成绘制和新鲜中立输入，然后申请控制租约。收到车端中立执行确认后才允许发送运动指令。整个过程仍要求可用的主视角证据。

## 同一辆车的证据

信令与控制是独立权限，但画面和控制目标必须一致：

1. 车辆发布媒体时声明其控制 session。信令服务端按令牌的 vehicle 角色、session 范围和 room 范围校验；同一信令连接不能切换发布 session。
2. 服务端提供发布者 principal、session 和连接 peer ID；principal 取自认证结果，客户端消息里的伪造身份不参与授权。
3. 接收端只接受房间内车辆发布者，给帧附加不可变来源。缺少或格式错误的来源信息不能当作可信画面。
4. 中继在 acquire 响应中返回实际绑定车辆的 `vehicle_principal`。驾驶端在发送第一条控制命令前比较 principal 与 session；不匹配就释放租约，不能因有权访问两个资源而把它们错误配对。

principal 应按真实车辆分别配置，不能让不同车辆共用同一身份/令牌。联合服务端和分开运行的两个模块须使用一致的身份定义。视频查看权限仍不授予控制权。

## 新鲜度与恢复

统一配置：

```yaml
video:
  primary_view: front
  stale_frame_ms: 500
  recovery_ms: 500
  max_capture_age_ms: 300
```

`primary_view` 可为 front/back/left/right；启用车辆媒体组件时必须有对应相机。500 ms 是当前模拟默认值，尚未验证为实车可接受阈值。

驾驶端同时检查本机接收时间和主帧采集年龄上界，以 Qt 的新帧 paintEvent 完成作为本地呈现证据。解码 PTS 不递增会关闭对应 peer；重复绘制同一帧、仅收到辅助视角、仅握手成功、仅将帧提交给控件 均不续期。画面隐藏或服务关闭立即撤销可用状态；即使 GUI 不再处理事件，控制工作线程仍按本机单调时钟判断证据过期。

主画面失效会立即禁止运动指令。驾驶端释放租约，车辆触发停车保护，仍在线的数据通道继续接收只读车况。画面即使在两次控制检查之间恢复，也会改变代次，使旧租约和在途租约申请失效。恢复需要连续新帧跨过 `recovery_ms`，驾驶员点击「恢复控制」后重新回中，再取得新租约和车端执行确认。

车辆媒体进程对主采集超时、设备打开失败和明确驱动异常分别隔离受影响的摄像头，清除其关联视角，并等待释放旧句柄后重试。其余摄像头继续供图。媒体与控制进程共享一个健康代次，控制端在取得租约、处理命令及看门狗检查时核对代次。故障使现有租约失效，所有故障相机重新供图后仍需新租约和中立输入。辅助视角单纯暂时缺帧只标记该视角过期。媒体进程本身崩溃或心跳中断仍触发整组故障处理。

全路中断后，若收帧恢复但主画面持续超过采集年龄预算，驾驶端在恢复窗口后按原有流程重建媒体连接。该窗口取接收超时与恢复时间的较大值。辅助视角单独断流时继续显示其他视角。

## 边界

驾驶端用探测往返中点对齐 RTP 采集时钟，并将半个往返时间计入年龄上界。半程超过 50 ms、时间锚点超过 5 s 或来源时间未知时禁止授权。默认采集年龄预算 300 ms 是独立的软件保护参数，覆盖本机四路软件基准的正常波动，不代表已验证的物理驾驶限值。当前相机采集时间记录 read 返回时刻，不是传感器曝光时刻；无法据此证明 USB 驱动没有缓存旧图像，也不能区分静止场景与设备重复返回的同一旧画面。持续有帧但链路积压造成的真实画面年龄，需要后续完整链路测量及真实设备时间戳验证。

Qt 绘制完成也不能证明显示器实际亮屏、未被别的窗口遮挡或驾驶员看到了画面。offscreen 测试只验证软件状态。真实显示/相机、弱网和底盘制动仍需验收；撤销租约、请求零速和结束进程都不代表已经获得物理停车确认。

驾驶端仍使用 Qt 工作线程，车端控制/媒体已分进程。仅启动车辆 control 可用于诊断或独立部署，但远程驾驶仍须有身份/session 匹配的媒体和驾驶端呈现证据。控制协议模拟脚本显式提供合成画面证据，不将它声称为实际视频验收。

## 升级与验证

旧字段 `ui.stale_frame_ms` 已迁到 `video.stale_frame_ms`。车辆信令 join 携带 session，joined/new_peer 由服务端提供画面来源，控制 acquire 返回 `vehicle_principal`。部署时使用同一修订的三个应用和共享包，当前注册修订见[控制协议](control-protocol-v2.zh-CN.md)。接收源退出通过 `on_invalidate` 通知。

`tests/test_video_safety.py` 覆盖新帧、重复帧、过期/恢复代次、Qt 绘制及隐藏、acquire 期间失效、真实 QUIC 的错车/错会话拒绝、恢复后回中，以及主摄像头阻塞时提前报告故障。信令测试另覆盖来源伪造、session 越权/类型错误/同连接切换和缺失来源元数据。实际回环控制/视频与分进程回归继续运行。

最初引入主视角授权时，全量回归有 235 项通过。完整 GUI 测试使用真实回环 WSS/WebRTC/QUIC、Qt offscreen 和模拟 USB/底盘，验证主画面隐藏导致撤销及模拟零速、恢复后保持油门仍被禁止、回中后取得新 epoch。三个应用分别从 wheel 独立安装检查通过。
