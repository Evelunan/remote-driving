# 主视角失效与控制授权

驾驶端默认只有在主视角持续收到新帧、Qt 完成这些帧的绘制、画面车辆与控制目标匹配后，才申请控制租约。取得租约后还需要新鲜中立输入及车端执行确认。没有视频检查对象或没有画面证据的控制客户端保持禁止状态，不提供配置开关绕过该条件。

## 同一辆车的证据

信令与控制是独立权限，但画面和控制目标必须一致：

1. 车辆发布媒体时声明其控制 session。信令服务端按令牌的 vehicle 角色、session 范围和 room 范围校验；同一信令连接不能切换发布 session。
2. 服务端提供发布者 principal、session 和连接 peer ID；principal 取自认证结果，客户端消息里的伪造身份不参与授权。
3. 接收端只接受房间内车辆发布者，给帧附加不可变来源。缺少或格式错误的来源信息不能当作可信画面。
4. 中继在 acquire 响应中返回实际绑定车辆的 `vehicle_principal`。驾驶端在发送第一条控制命令前比较 principal 与 session；不匹配就释放租约，不能因有权访问两个资源而把它们错误配对。

principal 应按真实车辆分别配置，不能让不同车辆共用同一身份/令牌。联合服务端和分开运行的两个模块须使用一致的身份定义。视频查看权限仍不授予控制权。

## 新鲜度与恢复

统一配置：

```yaml
video:
  primary_view: front
  stale_frame_ms: 500
  recovery_ms: 500
```

`primary_view` 可为 front/back/left/right；启用车辆媒体组件时必须有对应相机。500 ms 是当前模拟默认值，尚未验证为实车可接受阈值。

驾驶端以本机接收时间计算帧年龄，以 Qt 的新帧 paintEvent 完成作为本地呈现证据。解码 PTS 不递增会关闭对应 peer；重复绘制同一帧、仅收到辅助视角、仅握手成功、仅设置 pixmap 均不续期。画面隐藏或服务关闭立即撤销可用状态；即使 GUI 不再处理事件，控制工作线程仍按本机单调时钟判断证据过期。

任何失效都会改变检查对象的代次。画面即使在两个控制检查之间恢复，原租约也不能继续使用。恢复须连续有新帧跨过 recovery_ms，然后接收采样时间不早于恢复时刻的中立输入，并重新取得租约和执行确认；持续保持油门不能因画面回来而自动恢复运动。等待 acquire 时发生的画面失效也会使该申请结果失效。

车辆媒体进程同时检查主相机的采集序号与本机采集时间。没有新主帧、序号不再推进或主帧过期会报告组件故障；先通知父进程，再等待可能阻塞的相机/连接清理。父进程随后停止控制组件，控制执行与独立超时监护仍归 control 进程所有。当前其他相机的明确驱动异常也会使媒体组件失败；辅助视角只是暂时不更新时，只清除该视角，不冒充主画面健康。

## 边界

本机接收年龄不是跨主机的视频端到端延迟。当前相机采集时间记录 read 返回时刻，不是传感器曝光时刻；无法据此证明 USB 驱动没有缓存旧图像，也不能区分静止场景与设备重复返回的同一旧画面。持续有帧但链路积压造成的真实画面年龄，需要后续完整链路测量及真实设备时间戳验证。

Qt 绘制完成也不能证明显示器实际亮屏、未被别的窗口遮挡或驾驶员看到了画面。offscreen 测试只验证软件状态。真实显示/相机、弱网和底盘制动仍需验收；撤销租约、请求零速和结束进程都不代表已经获得物理停车确认。

驾驶端仍使用 Qt 工作线程，车端控制/媒体已分进程。仅启动车辆 control 可用于诊断或独立部署，但远程驾驶仍须有身份/session 匹配的媒体和驾驶端呈现证据。控制协议模拟脚本显式提供合成画面证据，不将它声称为实际视频验收。

## 升级与验证

旧字段 `ui.stale_frame_ms` 迁到 `video.stale_frame_ms`；旧字段不被静默忽略。车辆信令 join 增加 session，joined/new_peer 增加服务端来源信息；控制 acquire 增加 vehicle_principal。注册请求/响应增加 `revision: video-bound/1`；服务端明确拒绝缺少/不匹配修订的旧注册，返回 protocol_upgrade_required。应用还必须显式向共享 QUIC 连接传入修订参数；单独升级共享包不会让旧应用自动声称具备新检查。三个应用和共享包须协同升级，缺少这些信息时不降级为可驾驶状态。`WebRTCReceiver.on_frame` 回调签名改为 `(track_id, pixels, source)`；接收源退出通过 on_invalidate 通知。

`tests/test_video_safety.py` 覆盖新帧、重复帧、过期/恢复代次、Qt 绘制及隐藏、acquire 期间失效、真实 QUIC 的错车/错会话拒绝、恢复后回中，以及主摄像头阻塞时提前报告故障。信令测试另覆盖来源伪造、session 越权/类型错误/同连接切换和缺失来源元数据。实际回环控制/视频与分进程回归继续运行。

本阶段最终全量回归 235 项通过。完整 GUI 测试使用真实回环 WSS/WebRTC/QUIC、Qt offscreen 和模拟 USB/底盘，验证主画面隐藏导致撤销及模拟零速、恢复后保持油门仍被禁止、回中后取得新 epoch。三个应用分别从 wheel 独立安装检查通过。
