# 视频性能测量与改造记录

当前保留 aiortc、OpenCV 和 PyQt 路线，没有切换媒体后端或启用硬件编解码。下列结果按测量边界分别报告，不能相互替代。

## B11：驾驶端帧缓存

旧实现每次 `FrameBuffer.get()` 都深复制图像，显示组件在复制后才根据帧 ID 丢弃重复帧。新实现由生产者在发布时复制一次，缓存持有只读快照，轮询仅取得引用和版本。复制在元数据锁外完成，读者持有的旧快照不会被下一帧覆盖。会话代次在复制前后均检查，关闭或重连后的旧回调不能恢复旧画面。

显示时间调试文字改为可选 Qt 覆盖层，默认关闭，不再原地修改像素。没有新接收帧达到阈值时清除画面和 FPS/尺寸，显示“接收画面已过期”；新帧到达后恢复。此处依据本地接收时间，尚不能识别发送端把旧相机图像重复编码成新帧的情况，采集源新鲜度仍需继续改造。

### 复现

在已安装工作区依赖的 Python 3.12 环境执行：

```bash
.venv/bin/python scripts/benchmark_frame_buffer.py --output /tmp/frame-buffer-comparison.json
.venv/bin/python -m pytest -q tests/test_frame_cache.py
```

基准使用固定随机种子 42，一路 1080×720、三路 640×480 的 BGR 图像；输入 30 FPS，轮询 200 Hz，逻辑时长 3 秒，预热后重复 5 次。使用逻辑调度而非 sleep，统计此工作负载消耗的进程 CPU 和墙钟时间，不将逻辑秒数当作实际运行时长。NumPy 数组的 `copy()` 计数记录复制次数和载荷字节；不代表硬件内存总线流量。

改造前代码完整保存于 [基准快照](../benchmarks/baselines/frame_buffer_before_b11.py)，来源为提交 `9ec4447`。报告记录新旧代码 SHA256、Python、NumPy 和操作系统版本。[改造前报告](../benchmarks/results/frame-buffer-b11-before.json) 在改写实现前生成；[对比报告](../benchmarks/results/frame-buffer-b11-comparison.json) 在同一主机、同一脚本内依次运行新旧实现。

本次环境为 WSL2/Linux、Python 3.12.16、NumPy 2.4.4。CPU/墙钟数值受宿主机负载影响；没有调用相机、编码器、网络、Qt 或 GPU。

| 指标，每 3 秒逻辑负载 | 改造前 | 改造后 |
| --- | ---: | ---: |
| 发布帧数 / 不重复显示帧数 | 360 / 360 | 360 / 360 |
| 图像复制次数 | 2,400 | 360 |
| 复制载荷字节 | 3,058,560,000 | 458,784,000 |
| CPU 中位耗时 | 128.99 ms | 22.13 ms |
| 墙钟中位耗时 | 128.98 ms | 22.12 ms |

同一工作负载复制载荷减少 **85%**，缓存部分 CPU 耗时约减少 **82.8%**。不能据此宣称整体视频帧率、端到端延迟或编码性能改善相同比例。

### 正确性与剩余验证

回归覆盖输入数组复用、快照只读与保留、复制期间关闭会话、过期边界、非法图像，以及 Qt offscreen 显示/过期/恢复。原有可选 OpenGL 组件也改为消费快照、只上传新帧、分辨率改变时重新分配纹理，使用 BGR 和单字节行对齐；测试只模拟 GL 调用验证契约，默认显示路径仍为普通 PyQt 组件，真实 GPU/桌面验收待完成。

后续须完成采集源与订阅者隔离、采集停止后的帧过期、统一帧率、信令和媒体关闭重连；再补充单路/四路完整媒体链路的 CPU、RSS、事件循环延迟、编码/接收 FPS、首帧/重连耗时和网络统计。真实相机、TURN、受限网络、硬件编解码和跨主机端到端延迟需在目标设备上验收。
