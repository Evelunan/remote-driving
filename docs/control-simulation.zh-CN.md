# 无硬件控制链路验证

B10 使用真实 DrivingControlClient、VehicleControlClient 和认证 QUIC 中继，连接内存 MockController。它验证注册、租约、中立执行门控、配置限值、输入新鲜度、失效撤销和新代次恢复，不打开 USB、摄像头、串口或 ROS。

当前正式 GUI/CLI 入口仍在迁移，不能把该模拟结果当作默认入口已切换新版协议。新版控制客户端已经接收不可变配置；后续入口应直接使用这些客户端，不能再复制连接/握手实现。

## 复现

在已安装工作区依赖的 Python 3.12 环境运行：

~~~bash
uv sync --all-packages --group dev --python 3.12
uv run --no-sync python scripts/simulate_control.py --output /tmp/control-simulation.json
~~~

脚本只绑定回环地址，自动生成临时证书和随机令牌；运行结束删除临时证书并关闭客户端、监听器和设备线程。默认保持模拟运动目标 1 秒，可用 --motion-seconds 调整为 0.1–60 秒。

流程为新鲜中立输入 → 获得租约/执行确认 → 模拟运动 → 停止输入采样 → 请求零速并撤销租约 → 新鲜中立输入 → 取得新 epoch。末尾恢复输入后仍保持中立，不自动恢复之前的运动目标。

[本机记录](../benchmarks/results/control-b10-local.json)来自 Python 3.12.16、WSL2，仅用于确认工具和软件路径。模拟限值为 1.2 m/s、0.4 rad/s；项目默认的 5.0 m/s、2.0 rad/s 未改变。

| 报告字段 | 含义 |
| --- | --- |
| execution_acks | 设备 API 完成后收到的执行确认数量 |
| capture_to_ack_ms_* | 原始采样到收到执行确认的本机单调时钟耗时；包含输入停止后有效期内的重复样本，不是网络 RTT |
| input_expiry_to_mock_zero_target_ms | 停止模拟采样后，内存底盘观察到零速目标的耗时，不是物理停车时间 |
| new_epoch_after_neutral_recovery | 新鲜中立输入后是否获得不同的租约代次 |
| device_threads_closed | 设备执行与监护线程是否正常退出 |
| physical_stop_verified | 固定为 false；没有真实底盘反馈 |

该报告没有视频性能对比，不能替代后续视频基准、弱网测试或实车验收。一次运行的延迟不能作为部署阈值。

## 客户端约束

两端验证服务器证书和主机名；握手、注册和首次时钟探测有超时。服务器的 max_clock_skew_ms 是两端之间的误差预算，每端相对服务器各预留一半。探测使用请求前后时间区间的保守误差上界，不假定上下行延迟对称；网络不确定性或时钟偏差过大时拒绝控制，不能自动改写采样时间绕过检查。连接期间每秒重新探测，并比较本机墙钟和单调时钟，墙钟跳变会撤销连接。

驾驶端等待新鲜中立输入后申请租约，收到中立执行确认后才发送运动目标。输入失效或执行确认超时会可靠释放租约并关闭连接。重复发送仍保留原始采样时间；停顿后不突发补发积压命令。

车端以独立监护/执行线程消费最新有效命令，按已消耗的采样年龄缩短 watchdog 预算。API 执行完成后才发 EXECUTION；不生成虚假实测速度。设备调用阻塞时，独立停车接口仍可收到通知，但软件不能强杀已经进入硬件库的调用，也不能据此保证物理停车。

测试还覆盖仅重启驾驶端、旧连接回调、执行 ACK 丢失、阻塞设备、证书主机名不匹配、时钟预算不兼容及强制关闭期限。真实 ROS2、底盘 watchdog/制动和传感器反馈仍需部署方接入验收。

B16 后控制客户端默认要求主画面证据。本脚本显式生成带匹配模拟车辆身份/session 的合成新鲜度事件，以单独验证控制链路；这些事件没有经过摄像头、WebRTC 或 Qt，不能作为视频联动验收。实际回环视频与 Qt 呈现测试见 [主视角策略](video-safety.zh-CN.md)。
