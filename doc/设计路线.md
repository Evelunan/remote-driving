主要研究内容/任务要求
1.	系统总体架构设计
构建远程驾驶系统整体框架，划分视频采集与传输、控制指令通信、信令交互等核心模块，明确各模块之间的数据流与控制流关系。
2.	低延迟视频传输与实时处理
基于 WebRTC 实现多路摄像头视频的采集、编码、传输、解码与渲染，优化视频处理流程，降低端到端延迟并提升画面流畅性与稳定性。
3.	控制指令采集与可靠传输
设计驾驶端控制数据（转向、油门、制动等）的采集方式，构建低延迟、高可靠的控制指令传输机制。
4.	系统实现与性能评估
开发远程驾驶原型系统，对端到端延迟、帧率、丢包率等关键性能指标进行测试与分析，验证系统的可行性与稳定性。
系统结构说明
本系统采用“车辆端—服务器—驾驶端”的三层架构设计，通过视频链路与控制链路协同，实现远程驾驶闭环控制。
车辆端
1.	四路摄像头视频采集：通过多路摄像头采集车辆周围环境信息，并进行编码压缩；
2.	视频发送：基于WebRTC将视频数据实时发送至远程端；
3.	控制指令接收：接收来自服务器转发的控制指令；
4.	控制指令执行：将控制指令转化为车辆底层控制操作（转向、加速、制动等）；
服务器
1.	WebRTC信令服务：负责WebRTC建立连接过程中的信令交换（如 SDP、ICE 信息）；
2.	QUIC控制转发服务：基于QUIC协议转发驾驶端发送的控制指令至车辆端；
驾驶端
1.	视频接收：接收来自车辆端的视频帧
2.	视频渲染显示：实时渲染显示接收的视频帧
3.	控制指令采集：采集并处理来自方向盘和踏板的原始数据
4.	控制指令转发：将操作数据编码后，通过 QUIC 通道发送至服务器；


技术路线
1.	视频传输
为实现低延迟、高流畅的视频传输，系统采用基于 WebRTC(aiortc) 的实时音视频通信方案，结合多路摄像头数据处理与自适应编码机制，具体流程如下：
（1）视频采集与预处理
车辆端通过多路摄像头采集环境视频数据，利用 OpenCV（opencv-python） 完成图像获取与基础处理（格式转换、分辨率调整等）。
（2）视频编码与封装
优先采用H.264 编码 对视频流进行压缩，并封装为 WebRTC 可传输的媒体流（VideoStreamTrack），通过 aiortc 实现编码与发送逻辑。

（3）WebRTC连接建立
基于 WebSocket（websockets库） 构建信令通道，完成以下过程：
SDP（Offer/Answer）交换，实现编解码能力协商
ICE Candidate 交换，实现 NAT 穿透与路径选择
（4）媒体数据传输
优先采用 P2P 直连（UDP） 进行视频传输，在复杂网络环境下自动回退至 TURN 中继，保证连接稳定性。
（5）自适应优化机制
基于带宽估计调整码率；
动态控制帧率与分辨率；
实现拥塞控制，提高传输稳定性。
2.	控制指令传输
针对远程驾驶中控制指令“高实时性 + 高可靠性”的需求，系统采用基于QUIC（aioquic）的轻量级传输方案，具体流程如下：
（1）控制数据采集
驾驶端通过方向盘、踏板等设备采集控制数据（转向角、速度等）；
（2）轻量化协议编码
设计轻量化控制协议，对数据进行紧凑编码：
包含 type、session、seq 等基础字段；
包含 speed、steering 等控制量；
引入 timestamp 用于时延分析。
（3）QUIC连接建立
基于 aioquic 库建立 QUIC 连接。QUIC 协议基于 UDP 实现，具备低连接建立时延、多路复用及内置可靠性控制等特性，能够有效提升控制指令的传输效率。
（4）数据传输机制
采用 QUIC Datagram 机制传输控制数据，从而避免传统可靠传输中的队头阻塞问题，实现低延迟的数据传输
（5）可靠性与稳定性增强
为进一步提升系统的可靠性，设计了基于序列号的丢包检测机制，并结合时间戳实现端到端时延计算。同时，通过周期性发送心跳（heartbeat）消息，维持连接状态并检测链路可用性，从而保障控制链路的稳定运行。
3.	信令与连接管理
WebRTC信令服务：
视频链路基于WebRTC实现，其信令部分采用WebSocket构建独立信令通道，整体技术路线如下：
驾驶端与车载端通过WebSocket接入信令服务器，建立控制连接； 
基于房间机制完成节点发现与会话组织（driver ↔ vehicle）； 
通过信令通道交换SDP（offer / answer），完成媒体能力协商； 
转发ICE candidate，实现NAT穿透与最优路径选择； 
最终建立基于 UDP 的端到端媒体通道；
QUIC转发服务：
控制链路基于 QUIC 构建，实现连接管理与数据转发，具体流程如下：
驾驶端与车辆端分别接入转发服务，发送 hello-driving 与 hello-vehicle 完成身份注册； 
服务器根据注册信息建立会话绑定关系，并维护驾驶端与车辆端之间的映射； 
在控制面建立后，客户端基于 QUIC（UDP）建立数据传输连接； 
控制数据通过 QUIC Datagram 方式发送，实现低延迟、无阻塞的数据传输； 
驾驶端与车辆端周期性发送 heartbeat 消息，用于维持连接状态并检测链路可用性； 
服务器根据会话映射关系对控制数据进行转发，实现 driver → vehicle 的实时控制路径，并支持双向通信。
