# 驾驶端

每路视频信息框的“画面延迟”估算当前已绘制帧距车辆端读取该帧的毫秒数，包含编码、传输、解码和界面等待。驾驶端通过 WebRTC 定期将各路 RTP 时间戳对齐到本地时钟，上下行耗时不对称会影响估算。首次校时、画面过期或对端缺少计时支持时显示 `--`。摄像头曝光和显示器扫描耗时需另行实测。

进入驾驶控制页面时自动探测一次 USB 控制设备；未找到或连接失败后停止自动重试。在右侧“系统连接”的“控制设备”行点击“连接”可再尝试一次，连接中或已连接时按钮禁用。设备状态显示“未连接 / 连接中 / 已连接”。设备拔出后立即使输入失效，清理连接后等待手动连接；该按钮不重启视频或网络服务。

重连操作放在对应状态行右侧：信令服务器与 WebRTC 的“重连”共用媒体重连流程（重新认证、加入房间、建立视频），操作期间两个按钮同时禁用；视频流是接收状态，没有独立连接。数据通道的“重连”只重建 QUIC 控制客户端，等待旧租约及连接清理，不重启 USB 采样或视频。媒体重连会清空旧画面并撤销控制授权，恢复后仍需新鲜画面、归零输入和执行确认。

数据通道已认证且主画面可用时，输入等待提示按原因区分：设备未连接显示“等待控制设备”；没有有效新采样显示“等待设备输入”；新采样的油门或转向非零显示“请将控制输入归零”。这里的归零指油门与转向为零，不要求松开制动。收到主画面就绪后的新鲜中立输入后，继续等待车端执行确认才授权控制。

驾驶端启动时默认前进挡。挡杆上拨选择前进挡，下拨选择倒挡，松开后保持当前挡位。踩右踏板时，前进挡发送正油门，倒挡发送负油门。两个挡位下，只要解码出的制动值大于零，车辆端就请求零线速度和零角速度。当前控制器将两个踏板合并到一个轴，同时踩下时只能读取合并后的值。

右侧统一为一个滚动列，依次是“驾驶端输入”“车辆反馈”“系统连接”和各路视频统计。输入和反馈两组相邻，连接与视频统计不再插在两组之间。

“驾驶端输入”集中显示所选挡位、油门输入（0–100%）、制动输入（0–100%）、转向输入（带正负号的百分比）和输入有效状态。数据直接来自本地处理后的新鲜 USB 采样，最多每秒更新 20 次；不等待车辆连接、控制授权或指令执行确认。倒挡油门仍显示正的踏板百分比，方向由所选挡位表达；网络指令保持原有正负油门语义。输入无效、过期或设备断开时清空数值，网络断开不清除仍有效的本地输入。

“车辆反馈”内部包含“底盘实际状态”“指令确认”和可展开的“诊断详情”。指令确认显示接口已确认／待确认／确认已过期和采样至确认耗时；已确认指令的油门、制动及转向数值集中放在诊断详情。执行确认表示车端设备接口调用完成，不能证明物理动作或车辆已经停稳，也不会覆盖本地最新输入。

正式包名为 `rd-driving`，Python 命名空间为 `rd_driving`，入口为 `rd-driving`。使用 Python 3.10.12。

```bash
uv run --package rd-driving rd-driving --config configs/driving.yaml --dump-config
uv run --package rd-driving rd-driving --config configs/driving.yaml --check-config
uv run --package rd-driving rd-driving --config configs/driving.yaml --connect
```

[配置示例](../../configs/driving.yaml) 需要部署方提供 CA 文件与 `RD_OPERATOR_TOKEN`。`--dump-config` 不读取秘密值；`--check-config` 校验配置、凭据和 TLS，不启动 GUI 或打开 USB。默认打开会话选择页面；`--connect` 使用配置的 session/room 连接，或同时提供 `--session 1234 --room 1234`。会话和房间是独立资源 ID，真实授权由服务端核验，页面确认参数不代表认证成功。

正式入口使用 `rd_core` 不可变配置和 v2 QUIC 客户端；旧模块内 YAML 与单例加载器已删除。USB VID/PID、界面主题/尺寸/刷新周期、网络及凭据引用均由同一配置实例注入，优先级和迁移字段见[配置说明](../../docs/configuration.zh-CN.md)。

输入在 USB 读取完成时记录采样时间，经最新值队列按固定周期发送。有效中立输入及车端执行确认后才允许运动；输入失效或确认过期撤销控制。界面分别显示控制器接口执行确认、采样至确认耗时和底盘实际反馈；反馈值过期/断联清除，不用控制目标冒充车速。停车物理确认仍未接入。

“车辆反馈”的底盘实际状态显示车速（m/s）、转向角（°）、反馈挡位、自动驾驶使能和底盘制动反馈；诊断详情集中放置左右轮速（m/s）、驾驶模式原始编码、已确认指令值、已有独立遥测和停车确认说明。反馈挡位显示“D 前进（1）”“N／停止（2）”“R 倒退（3）”，未知值显示“未知（编码）”，缺失字段显示 `--`。底盘源码的 N 与底盘说明中的“停止”均不作为已经停稳的证明。

输入、接口确认、底盘反馈分别使用自己的原始采样有效期，界面排队不会刷新期限。反馈过期或断联时清空旧值；输入过期不清空仍新鲜的底盘反馈。静止选择 D/R 时底盘可能仍反馈 2，踩制动后 `p_status` 也可能仍为 false：目前控制链路按速度正负推导档位、将制动输入转换为零速请求。这些差异由组内说明解释，不触发“挡位不一致”或“制动失败”告警。

本功能通过当前认证控制租约接收反馈，主画面、输入与授权条件仍适用，未增加独立的只读监控通道。车速依据用户 2026-11-24 确认的 m/s 原值接收与显示；三端及共享包须配套升级到 `vehicle-status/2`，不能与按 km/h 解释状态的 `vehicle-status/1` 混用。驾驶模式描述底盘控制来源，自动驾驶使能描述实体按钮状态；模式编码在底盘说明和源码注释间存在冲突，因此保留原始值。配置和人工验收见[车辆端状态反馈](../vehicle/README.md#ros2-底盘状态反馈)。

PyQt6 需要可用显示环境。OpenCV 导入封装保留用户原有 Qt 插件/字体路径，避免第三方 wheel 覆盖；offscreen 验证不代表真实桌面、GPU 或设备验收。构建命令见[根 README](../../README.md)，剩余工作见[实施记录](../../docs/refactoring-progress.zh-CN.md)。

主画面必须经过 Qt 新帧绘制、新鲜度与车辆身份/session 校验才能授权控制。过期、隐藏或来源更换撤销授权；恢复须新帧稳定、新采样回中和执行确认，详见 [画面与控制](../../docs/video-safety.zh-CN.md)。

正式 GUI 从 B23 起将 `SIGINT`、`SIGTERM`转入窗口异步关闭流程，等待控制/媒体线程结束；重复信号不强行跳过清理。Python 信号处理器仅标记待退出，由 Qt 的 50ms 定时检查触发关闭，并在事件循环结束时恢复原处理器。此间隔不是实时上限：GUI/native 调用阻塞时仍可能延迟，进程管理器超时与远端控制监护继续承担故障兜底。依据 [Python 信号调度](https://docs.python.org/3.10/library/signal.html#execution-of-python-signal-handlers)与 [Qt 定时器](https://doc.qt.io/qt-6/qtimer.html)。
